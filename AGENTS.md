# PROJECT RULES: ЕОРП «ВЕКТОР» / school-platform-v2

## 1. Цель
Перенести Flask/SQLite в FastAPI + React + PostgreSQL + Android/iOS без потери
функций и данных, затем расширить до республиканского уровня.

## 2. Стек
- Backend: Python 3.12/3.13, FastAPI, SQLAlchemy 2.0 async, Alembic, asyncpg.
- БД: PostgreSQL 16+; Redis для кеша, очередей и сессий.
- Frontend: React 18+ + TypeScript, Vite, TailwindCSS, React Router, Axios.
- Mobile: Flutter, Android/iOS, Hive/SQLite.
- AI: OpenRouter/OpenCode через OpenAI-совместимый API.
- Файлы: S3-совместимое хранилище; Markdown — источник, DOCX — версия.

## 3. Критические правила
1. Не удаляй функции и данные старого проекта, пока эквивалент не принят.
2. Сначала анализируй старый код и фиксируй требования, затем предлагай FastAPI.
3. Не меняй схему БД без миграции Alembic.
4. Не коммить секреты, токены, пароли и реальные ПДн.
5. ПДн детей — только в защищённых полях, с аудитом и минимальным сроком.
6. Изменение поведения API — в `docs/10-reporting/04-zhurnal-izmeneniy.md`.
7. Перед задачей читай `activeContext.md` (≤ 4 КБ) и первые 40 строк
   `progress.md`; полную историю — только по запросу.
8. После задачи обнови `activeContext.md` и допиши `progress.md`.
9. Не меняй `AGENTS.md` и skills посреди сессии без необходимости: это ломает
   prompt-cache. Меняй их отдельным коммитом.
10. `browser*` и `opencode*` инструменты выключены глобально. Для UI-проверок
    используй `@browser`; worktree/session — через CLI.

## 4. Архитектура
- API-first: web, Android и iOS используют один API.
- Мультитенантность: изоляция по `school_id`; проверка в API и, где возможно, RLS.
- Мультиязычность: JSONB `{"ru": "...", "by": "...", "en": "..."}`; UI — i18n.
- Только async-драйверы БД и async HTTP-клиенты.
- Идемпотентность для синхронизации, платежей и документов.
- Offline-first для mobile: очередь, повтор, правила разрешения конфликтов.
- Модульный монолит; выделение сервисов — только при доказанной необходимости.

## 5. Код
- Python: PEP 8, Ruff, mypy по возможности, Pydantic v2.
- TypeScript: strict, ESLint, функциональные компоненты и хуки.
- Flutter: null safety, слои data/domain/presentation.
- Новый эндпоинт — pytest; новый экран — widget/интеграционный тест.
- Публичные API — через OpenAPI/Swagger.

## 6. Документация
- Официальные документы — `docs/`; исходники Markdown, версии DOCX.
- Отчёты — по шаблонам `docs/10-reporting/`.
- Решения, отклонения и риски — в журналах.
- Перед сдачей этапа — матрица соответствия требованиям.

## 7. Безопасность
- Пароли — Argon2id или bcrypt с безопасными параметрами.
- JWT: короткий access + refresh с ротацией.
- Внешние вызовы — с таймаутами, retry и лимитом ответа.
- Загрузки — MIME, размер, антивирусная проверка на сервере.
- Логи без паролей, токенов, полных номеров документов и лишних ПДн.
- Production: HTTPS, WAF, rate limiting, backup, мониторинг.

## 8. Поведение агента
- Один шаг — одна проверяемая задача; не пиши весь проект сразу.
- Перед изменением файлов кратко опиши план.
- После изменений запускай релевантные тесты и показывай результат.
- Неоднозначное требование — задай вопрос; юридически значимое не выбирай сам.
- Destructive-команды — только с явным подтверждением.
- После задачи кратко обнови `activeContext.md` и `progress.md`.

## 9. Экономия токенов
- Сначала `docs/INDEX.md`, `docs/CODEMAP.md` или `docs/api/ENDPOINTS.md`,
  затем 1–2 конкретных файла/раздела. Не читай документ целиком.
- Поиск — `rg`; чтение — не более 200 строк; без рекурсивных листингов.
- Запрещено читать: `docs/word/**`, `node_modules`, `.venv`, `backups`,
  `*.docx`, `.env*`, `secrets`, `package-lock.json`.
- Перед чтением изменённых файлов: `git status --short` и `git diff --stat`.
- Повторяемые операции — через skills и команды `/check`, `/test`, `/docs`,
  `/api`, `/release`, `/pilot-status`, `/db-schema`.
- `/check` и `/test` идут через `test-runner`; `/docs`, `/api`, `/release`,
  `/db-schema`, `/pilot-status` — в `build` + `subtask`.
- Поиск — `@explorer`; ревью — `@reviewer`; документы — `@docs-writer`;
  браузер — `@browser`. `@general` — только по необходимости.
- Библиотечная документация — Context7; webfetch только если Context7 мало.
- Проверка: `scripts/check.ps1`; показывай итог и последние 40 строк при падении.
- DOCX — только в фоне; не запускай генерацию в основном контексте.
