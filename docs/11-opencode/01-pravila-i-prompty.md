## 1. Назначение
Документ описывает, как вести разработку в OpenCode: какие файлы читать,
как формулировать задачи, как проверять результат и обновлять память.

## 2. Обязательные файлы
- `AGENTS.md` — правила проекта, включая раздел 9 об экономии токенов.
- `.opencode/memory-bank/projectbrief.md` — краткое описание.
- `.opencode/memory-bank/architecture.md` — архитектура.
- `.opencode/memory-bank/activeContext.md` — текущая задача (≤ 4 КБ).
- `.opencode/memory-bank/progress.md` — последние этапы; полная история —
  `archive/progress-2026.md` (только по запросу).
- `docs/INDEX.md` — индекс документации.
- `docs/CODEMAP.md` — карта кода.
- `docs/api/ENDPOINTS.md` — индекс эндпоинтов OpenAPI.
- `.opencode/skills/`, `.opencode/commands/`, `.opencode/agents/` — повторяемые
  сценарии, команды и подагенты.

## 3. Настройка OpenCode
- Конфигурация: `opencode.json` (формат OpenCode 1.19.x). Локальная БД
  OpenCode имеет схему V2; для CLI-команд `db`/`models` нужен V2-бинарник
  или обновление CLI.
- Модели: `model` — `opencode/deepseek-v4.1-flash-free`; `small_model` —
  `opencode/claude-haiku-5-5`; `explorer`, `test-runner`, `docs-writer` и
  `browser` — на бесплатной модели; `reviewer` — на основной.
- Права: `bash` — allowlist (`git status/diff`, `rg`, `pytest`, `ruff`, `tsc`,
  `scripts/check.ps1`, сборка и генераторы); `edit` — `ask`; `webfetch` —
  `allow`.
- `read` запрещает `docs/word`, `node_modules`, `.venv`, `backups`, `.env*`,
  `secrets`, `*.pem`, `*.key`, `package-lock.json`.
- `browser*` и `opencode*` выключены; для UI — `@browser`; `general` — только
  с подтверждением.
- Подагенты: `explorer` (поиск), `reviewer` (ревью), `test-runner` (тесты),
  `docs-writer` (документы), `browser` (UI). Команды `/check`, `/test`,
  `/docs`, `/api`, `/release`, `/db-schema`, `/pilot-status` — `subtask`;
  лимиты шагов — 10–50.
- `compaction.prune: true`, `watcher.ignore` для `.git`, кешей, `secrets`,
  `.env*`, `docs/word`, `frontend/dist`.
- MCP PostgreSQL отключён; включать только read-only и только для отдельного
  подагента/задачи, `DATABASE_URL` — из переменной окружения.
- Git: MinGit 2.56 в `C:\Users\adamrv\AppData\Local\MinGit\cmd` (добавлен в PATH).
- Замер экономии и ограничения — ШК-10-20.

## 4. Правила постановки задач
1. Одна задача — один проверяемый результат.
2. Указывать файлы и границы изменений.
3. Указывать, какие тесты запустить.
4. Запрещать удаление старого функционала без явного разрешения.
5. Требовать обновления документации и `progress.md`.
6. Для юридически значимых функций — сначала согласование, потом код.

## 7. Формат ответа агента
Агент должен:
1. Кратко описать план.
2. Перечислить изменённые файлы.
3. Показать результаты тестов кратко: итог и только падения.
4. Указать риски и незакрытые вопросы.
5. Обновить `activeContext.md` и дописать `progress.md`.
6. Не вставлять полные файлы и логи; использовать ссылки `file:line`.

## 8. Запреты
- Не удалять старый проект и его данные.
- Не коммитить `.env`, ключи, токены.
- Не менять продовую БД без резервной копии.
- Не включать внешние сервисы без согласования.
- Не принимать юридически значимые решения без человека.

## 9. Экономия токенов
### 9.1. Порядок чтения
1. `docs/INDEX.md` — найти документ.
2. `docs/CODEMAP.md` — найти модуль и файл.
3. `docs/api/ENDPOINTS.md` — найти маршрут.
4. Прочитать 1–2 конкретных файла или раздела, не весь каталог.

### 9.2. Жёсткие ограничения
- Не читать `docs/word/**`, `**/node_modules/**`, `**/.venv/**`,
  `backups/**`, `*.docx`, `.env`, `package-lock.json`.
- Поиск — `rg`/grep; чтение — не более 200 строк за раз.
- Не делать рекурсивный список каталогов без исключений.
- Не вставлять в ответ полные файлы, логи и вывод тестов.

### 9.3. Git и изменения
- Перед чтением изменённых файлов: `git status --short` и `git diff --stat`.
- Читать только изменённые участки; полный файл — если без него нельзя.
- Git: `C:\Users\adamrv\AppData\Local\MinGit\cmd\git.exe` или `git` после
  перезапуска терминала.

### 9.4. Повторяемые сценарии
- Skills: `add-endpoint`, `add-migration`, `add-service`, `docs-sync`,
  `release`, `pilot-deploy`, `test-triage`.
- Команды: `/check`, `/test`, `/docs`, `/api`, `/release`, `/pilot-status`,
  `/db-schema`.
- Подагенты: `explorer` (поиск), `reviewer` (ревью), `test-runner` (тесты),
  `docs-writer` (документы).

### 9.5. Проверки и генерация
- Единая проверка: `scripts/check.ps1`; показывать итог и последние 40 строк
  при падении.
- Индексы: `python scripts/gen_docs_index.py`,
  `python scripts/gen_codemap.py`,
  `python scripts/gen_api_index.py` (из `backend`).
- DOCX — только по команде и в фоне; в контекст — число файлов и имя
  объединённого.

### 9.6. Модели и MCP
- Сильная модель — архитектура, безопасность, ревью; дешёвая — поиск, тесты,
  summary, документы.
- MCP: максимум 1–2 сервера. PostgreSQL — read-only и только по необходимости;
  Context7 — для документации библиотек. Остальные — по доказанной потребности.
- Не менять `AGENTS.md` и skills посреди сессии без необходимости: это ломает
  prompt-cache.
