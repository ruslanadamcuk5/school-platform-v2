## 1. Назначение
Документ описывает, как вести разработку в OpenCode: какие файлы читать,
как формулировать задачи, как проверять результат и обновлять память.

## 2. Обязательные файлы
- `AGENTS.md` — правила проекта.
- `.opencode/memory-bank/projectbrief.md` — краткое описание.
- `.opencode/memory-bank/architecture.md` — архитектура.
- `.opencode/memory-bank/activeContext.md` — текущая задача.
- `.opencode/memory-bank/progress.md` — прогресс.

## 3. Настройка OpenCode
- Конфигурация: `opencode.json`.
- Права `bash` и `edit` — `ask`, чтобы агент не выполнял опасные команды без
  подтверждения.
- MCP PostgreSQL отключён до установки Node.js; после установки включить и
  указать реальный `DATABASE_URL`.
- Модель по умолчанию — `opencode/claude-sonnet-5-5`; при недоступности
  заменить на доступную модель.

## 4. Правила постановки задач
1. Одна задача — один проверяемый результат.
2. Указывать файлы и границы изменений.
3. Указывать, какие тесты запустить.
4. Запрещать удаление старого функционала без явного разрешения.
5. Требовать обновления документации и `progress.md`.
6. Для юридически значимых функций — сначала согласование, потом код.

## 6. Последовательность промптов
### Шаг 1. Анализ
См. стартовый промпт.

### Шаг 2. Каркас backend
```text
Создай каркас FastAPI в backend/app: main.py, config.py, database.py,
роуты /health, /ready, /version. Настрой async SQLAlchemy и Alembic.
Добавь pytest-тест healthcheck. Запусти тесты и покажи результат.
```

### Шаг 3. Модели и миграции
```text
Создай модели iam.users, iam.roles, iam.permissions, org.regions,
org.cities, org.schools, org.classes. Добавь Alembic-миграцию.
Не меняй старую БД. Напиши тест на создание пользователя и школы.
```

### Шаг 4. Аутентификация
```text
Реализуй регистрацию, вход, refresh, выход. Используй Argon2id и JWT.
Добавь зависимости get_current_user и require_permission. Напиши тесты
на запрет доступа ученика к админским маршрутам.
```

### Шаг 5. RBAC и иерархия
```text
Реализуй роли global_admin, region_admin, city_admin, school_admin,
teacher, student, parent, secretary, methodologist, psychologist.
Добавь проверку school_id и иерархии назначения. Покрой тестами.
```

### Шаг 6. Справочники и пользователи
```text
Реализуй CRUD для школ, классов, пользователей. Добавь пагинацию,
поиск, фильтры и аудит действий. Напиши тесты прав доступа.
```

### Шаг 7. Контент
```text
Реализуй subjects, topics, lessons, textbooks, files. Добавь загрузку
PDF в S3/MinIO, привязку тем к страницам и мультиязычные JSONB-поля.
Напиши тесты загрузки и выдачи контента.
```

### Шаг 8. Тесты и работы
```text
Реализуй quizzes, questions, answer_options, assignments, submissions,
answers. Поддержи типы ответов: выбор, текст, число, фото, аудио.
Добавь API прохождения и проверки. Покрой тестами.
```

### Шаг 9. ИИ-оркестратор
```text
Создай ai_service.py с адаптером OpenRouter. Реализуй генерацию теста,
объяснение темы и проверку ответа. Добавь лимиты, таймауты, логирование
без ПДн и fallback. Напиши тесты с моком внешнего API.
```

### Шаг 10. Журнал
```text
Реализуй journal.entries и lesson_schedule. Добавь выставление оценок,
посещаемость, права учителя/родителя/ученика и экспорт в Excel.
Покрой тестами.
```

### Шаг 11. Frontend
```text
Создай React + TypeScript + Vite + Tailwind. Настрой i18n, Axios,
AuthContext, защищённые маршруты. Сделай экраны входа, профиля и
карты тем. Напиши базовые тесты.
```

### Шаг 12. Родитель
```text
Реализуй мультидетность, статистику, задания, документы и уведомления.
Добавь проверку прав опекуна. Покрой ключевые сценарии E2E.
```

### Шаг 13. Школа и секретариат
```text
Реализуй расписание, отчёты, заявки на справки, PDF-генерацию и
подписи. Добавь права директора, завуча и секретаря. Покрой тестами.
```

### Шаг 14. Коммуникации
```text
Реализуй WebSocket-чаты, группы, опросы, анонимный чат психолога.
Добавь модерацию и уведомления. Покрой тестами.
```

### Шаг 15. Офлайн
```text
Реализуй /sync с operation_id и device_id, идемпотентность и правила
конфликтов. Добавь тесты повторной отправки и конфликтов.
```

### Шаг 16. Мобильное приложение
```text
Создай Flutter-клиент: вход, карта тем, работы, библиотека, профиль.
Настрой локальную БД, очередь синхронизации, push и Force Update.
```

### Шаг 17. Безопасность и аудит
```text
Добавь аудит, rate limiting, security headers, проверку загрузок,
маскирование ПДн в логах. Напиши тесты и проверь OWASP-риски.
```

### Шаг 18. Документация и релиз
```text
Обнови OpenAPI, README, руководства, матрицу требований и отчёты.
Подготовь чек-лист релиза и инструкцию отката.
```

## 7. Формат ответа агента
Агент должен:
1. Кратко описать план.
2. Перечислить изменённые файлы.
3. Показать результаты тестов.
4. Указать риски и незакрытые вопросы.
5. Обновить `progress.md`.

## 8. Запреты
- Не удалять старый проект и его данные.
- Не коммитить `.env`, ключи, токены.
- Не менять продовую БД без резервной копии.
- Не включать внешние сервисы без согласования.
- Не принимать юридически значимые решения без человека.
