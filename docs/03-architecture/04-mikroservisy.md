| Параметр | Значение |

| Версия | 1.0 |
| Статус | Рабочий |

## 1. Решение

Платформа развивается как **набор доменных микросервисов в едином
монорепозитории**. Каждый функциональный блок (журнал, библиотека, тесты,
аналитика, ИИ, документы и т. д.) оформляется как самостоятельный сервис:

- собственный каталог кода и границы домена;
- собственный набор моделей, схем, бизнес-логики и API;
- собственный манифест сервиса (код, версия, префикс API, права, зависимости);
- возможность запуска как в составе общего шлюза (пилот, разработка), так и
  отдельным FastAPI-приложением (промышленная эксплуатация, масштабирование);
- независимое включение и отключение для любой области иерархии
  (страна → область → город → школа → класс).

Такой подход сохраняет скорость разработки модульного монолита, но убирает
главный риск «монолита навсегда»: любой сервис можно выделить в отдельный
процесс, контейнер и контур без переписывания бизнес-логики.

## 2. Каталог сервисов

|---|---|---|---|---|---|---|---|
| `system` | Ядро, реестр сервисов, настройки | `/api/v1/services` | core | да | вкл. | Республиканский администратор | Все |
| `iam` | Пользователи, группы, права, сессии | `/api/v1/auth`, `/api/v1/groups`, `/api/v1/me` | core | да | вкл. | Администраторы всех уровней | Все |
| `org` | Регионы, города, школы, классы | `/api/v1/org` | core | да | вкл. | Республика, область, город, школа | Все |
| `audit` | Аудит, события ИБ | `/api/v1/admin` | security | да | вкл. | ИБ, республиканский администратор | ИБ, руководство |
| `lms` | Предметы, темы, уроки, учебники, курсы | `/api/v1/lms` | education | нет | вкл. | Методисты, школа | Учителя, ученики, родители |
| `assessment` | Тесты, работы, сдача, автопроверка | `/api/v1/assessment` | education | нет | вкл. | Учителя, методисты | Учителя, ученики, родители |
| `journal` | Расписание, оценки, посещаемость | `/api/v1/journal` | education | нет | вкл. | Школа, классные руководители | Учителя, ученики, родители |
| `library` | Библиотека и рекомендации | `/api/v1/library` | education | нет | вкл. | Учителя, библиотекарь, школа | Учителя, ученики, родители |
| `analytics` | BI, отчёты, выгрузки | `/api/v1/analytics` | analytics | нет | вкл. | Руководство, аналитики | Администраторы всех уровней |
| `ai` | ИИ-оркестратор | `/api/v1/ai` | ai | нет | выкл. | Республика, методисты | Учителя, ученики, методисты |
| `communication` | Мессенджер, объявления, видео | `/api/v1/communication` | communication | нет | вкл. | Школа, модераторы | Все |
| `safety` | Психология, инциденты, GPS | `/api/v1/safety` | security | нет | выкл. | Психологи, ИБ, школа | Психологи, родители, ученики |
| `documents` | Справки, заявления, подписи | `/api/v1/documents` | management | нет | выкл. | Секретариат, руководство | Секретариат, родители, сотрудники |
| `admin` | Статистика и управление | `/api/v1/admin` | management | нет | вкл. | Администраторы уровней | Руководство |

Каталог хранится в `system.services` и синхронизируется из
`backend/app/services/registry.py`. Один и тот же манифест задаёт:

- запись каталога;
- список публикуемых прав (`iam.permissions`);
- префикс API;
- правила активации по умолчанию;
- зависимости между сервисами.

## 3. Границы доменов

| Домен | Владеет данными | Не должен напрямую читать |
|---|---|---|
| IAM | пользователи, группы, права, сессии, согласия | учебные данные |
| Org | регионы, города, школы, классы, состав | оценки и контент |
| LMS | предметы, темы, уроки, учебники, файлы | персональные оценки |
| Assessment | тесты, вопросы, работы, ответы | журнал напрямую |
| Journal | расписание, оценки, посещаемость | содержимое учебников |
| Library | пособия, доступ классов, рекомендации | персональные ПДн вне связи |
| Analytics | агрегаты, снимки, отчёты | сырые ПДн без маскирования |
| AI | запросы, результаты, эмбеддинги | ПДн сверх минимума |
| Communication | чаты, уведомления, звонки | учебные оценки |
| Safety | обращения, инциденты, согласия GPS | открытые ПДн |
| Documents | шаблоны, заявки, подписи | лишние ПДн |
| Audit | события, трассировка | бизнес-содержимое |

Межсервисное взаимодействие — только через версионированный API или
события. Прямые запросы в чужие схемы БД запрещены, кроме аналитического
контура чтения через представления.

## 4. Режимы развёртывания

### 4.1. Общий шлюз (пилот и разработка)

Один процесс FastAPI монтирует все включённые роутеры. Это режим текущего
пилота: минимум инфраструктуры, быстрый цикл разработки.

### 4.2. Отдельный сервис (промышленная эксплуатация)

Каждый сервис запускается отдельным приложением:

```bash
uvicorn app.service_app:create_service_app --factory \
  --host 0.0.0.0 --port 8101
```

Переменная окружения `SERVICE_CODE` задаёт, какой сервис поднять. Шлюз
(Nginx/Kong/Traefik) маршрутизирует `/api/v1/<service>` на соответствующий
контейнер. Общие компоненты (JWT, tenant-контекст, аудит, rate limiting)
подключаются из `app.core` и `app.api.deps`.

### 4.3. Контракт сервиса

Каждый сервис обязан предоставлять:

- `GET /health` — состояние;
- `GET /openapi.json` — контракт;
- версионированный префикс `/api/v1/...`;
- проверку JWT и `school_id`/scope-контекста;
- идемпотентность операций синхронизации;
- структурные логи с `request_id`;
- метрики и трассировку;
- отсутствие ПДн и секретов в логах.

## 5. Включение и отключение функционала

### 5.1. Модель

Активация сервиса задаётся в `system.service_activations`:

- `service_code`;
- `scope_type` (`country`, `region`, `city`, `school`, `class`);
- `scope_id`;
- `enabled`;
- `config` (JSONB, параметры конкретной школы/города);
- кто и когда изменил.

### 5.2. Правила разрешения

1. Для пользователя строится дерево его областей: класс → школа → город →
   область → страна.
2. Выбирается **самая конкретная** активация сервиса.
3. Если активации нет — применяется значение по умолчанию из каталога.
4. Ядровые сервисы (`system`, `iam`, `org`, `audit`) отключить нельзя.
5. Отключение на уровне школы перекрывает включение на уровне страны.
6. Включение на уровне школы перекрывает отключение на уровне страны.

### 5.3. Что видит пользователь

Клиент вызывает `GET /api/v1/me/services` и строит навигацию только из
полученного списка. Дополнительно `GET /api/v1/me/permissions` возвращает
действующие права для скрытия/показа отдельных кнопок и действий.

Пример ответа:

```json
{
  "items": [
    {
      "code": "journal",
      "name": "Электронный журнал",
      "icon": "📔",
      "category": "education",
      "api_prefix": "/api/v1/journal",
      "status": "active",
      "enabled": true,
      "source": "activation",
      "permission_codes": ["journal.schedule.read", "journal.grades.read"]
    }
  ],
  "total": 1
}
```

### 5.4. Кто управляет

| Уровень | Может включать/отключать | Ограничения |
|---|---|---|
| Республика | все сервисы для страны, областей, городов, школ | ядро отключить нельзя |
| Область | сервисы для своих городов и школ | только внутри области |
| Город/район | сервисы для своих школ | только внутри города |
| Школа | сервисы для школы и классов | только внутри школы |
| Класс | отдельные учебные модули | только по делегированию |

Все изменения активаций пишутся в аудит: кто, когда, какая область, какое
значение было и стало.

## 6. Права сервиса

Сервис публикует права в манифесте. Права хранятся в `iam.permissions` и
назначаются **только группам**. Примеры:

- `journal.grades.read` / `journal.grades.write`;
- `library.recommendations.create`;
- `assessment.submissions.grade`;
- `system.services.write`;
- `iam.groups.write`.

Администратор сервиса не может выдать право, которого нет в каталоге.
Каждое право имеет область действия (`read`, `write`, `admin`, `use`) и
принадлежность к сервису.

## 7. Добавление нового микросервиса

1. Создать каталог `backend/app/services/<code>/` с моделями, схемами,
   роутером и бизнес-логикой.
2. Добавить манифест в `app/services/registry.py`: код, имя, префикс,
   категорию, права, зависимости, значение по умолчанию.
3. Добавить миграцию Alembic для схемы и таблиц.
4. Подключить роутер в `app/api/v1/router.py` (режим шлюза).
5. Добавить проверку `require_service("<code>")` и
   `require_permission("<code>.<action>")`.
6. Добавить тесты: контракт, права, tenant-изоляция, отключение сервиса.
7. Обновить документы ШК-03-04, ШК-04-02, ШК-03-03 и журнал изменений.
8. Добавить экран/навигацию во фронтенд через `/me/services`.

## 8. Нефункциональные требования

- Независимый деплой и откат сервиса.
- Горизонтальное масштабирование без общего состояния.
- Таймауты, retry, circuit breaker для внешних вызовов.
- Ограничение размера ответа и загрузок.
- Idempotency-Key для sync/платежей/документов.
- Совместимость API: версия в префиксе, устаревание через deprecation-политику.
- Наблюдаемость: `request_id`, метрики, трассировка, алерты.
- Изоляция ПДн: минимизация, маскирование, аудит доступа.
