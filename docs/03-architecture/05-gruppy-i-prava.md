## 1. Принцип

**Права назначаются группам, а не отдельным пользователям.** Пользователь
принадлежит одной или нескольким группам. Чтобы изменить его полномочия,
администратор перемещает пользователя между группами — все права
пересчитываются автоматически.

Пример: учитель сегодня назначен завучем. Администратор школы исключает его
из группы «Учителя» и добавляет в группу «Администрация школы». Пользователь
сразу получает права завуча, унаследованные от группы, без ручной настройки
каждого действия.

## 2. Модель

### 2.1. Области (scope)

Иерархия платформы:

```
страна (country)
  └── область (region)
        └── город/район (city)
              └── школа (school)
                    └── класс (class)
```

Каждая группа принадлежит ровно одной области. Страна использует
фиксированный идентификатор `00000000-0000-0000-0000-000000000000`, чтобы
уникальность работала одинаково на всех уровнях.

### 2.2. Категории групп

| Категория | Назначение |
|---|---|
| `students` | ученики |
| `teachers` | учителя-предметники, классные руководители |
| `administration` | директор, завучи, руководители органов управления |
| `methodologists` | методисты, авторы контента |
| `psychologists` | школьные и республиканские психологи |
| `secretaries` | секретариат, делопроизводство |
| `parents` | родители и законные представители |
| `other` | сервисные и временные группы |

Категория — это «функциональная полоса» наследования. Группа «Учителя 7А»
наследует права группы «Учителя школы», та — «Учителя города», и так до
республиканской группы учителей.

### 2.3. Сущности

- `iam.groups` — группа: код, имя, категория, область, глубина, родитель,
  системный флаг, активность, метаданные.
- `iam.group_memberships` — членство: группа, пользователь, кто назначил,
  когда, срок действия, основная ли.
- `iam.permissions` — каталог прав, публикуемых сервисами.
- `iam.group_permissions` — выдача права группе: `allow`/`deny`, кто выдал,
  когда, срок действия.

## 3. Наследование

Права пользователя складываются из:

1. **Прямых членств** — все активные группы пользователя.
2. **Явной цепочки родителей** — `parent_id` группы.
3. **Организационных предков** — группы той же категории на всех вышестоящих
   областях: класс → школа → город → область → страна.

Пример:

```
Группа «Учителя 7А» (class, категория teachers)
  родитель: «Учителя школы» (school, teachers)
    родитель: «Учителя города» (city, teachers)
      родитель: «Учителя области» (region, teachers)
        родитель: «Учителя республики» (country, teachers)
```

Если республиканская группа учителей получает право
`lms.content.read`, его автоматически получают все учителя всех школ.

## 4. Разрешение конфликтов

Правила детерминированы и проверяются unit-тестами:

1. **Более конкретная область побеждает.** Право, выданное на уровне класса,
   перекрывает право на уровне школы, города, области и страны.
2. **При равной глубине `deny` побеждает `allow`.** Это позволяет точечно
   запретить действие, не разрушая общую матрицу.
3. **Срок действия.** Просроченные членства и выдачи игнорируются.
4. **Отключённая группа.** Права неактивной группы не учитываются.
5. **Отключённый сервис.** Даже при наличии права сервис недоступен, если
   отключён для области пользователя.

Пример:

| Область | Право | Эффект |
|---|---|---|
| Страна | `journal.grades.write` | allow |
| Школа | `journal.grades.write` | deny |
| Класс | `journal.grades.write` | allow |

Итог для ученика класса: **allow** (класс — самая конкретная область).
Итог для учителя школы без класса: **deny** (школа конкретнее страны).

## 5. Типовая матрица групп

| Группа | Примеры прав |
|---|---|
| Ученик класса | `lms.content.read`, `assessment.submissions.submit`, `journal.grades.read`, `library.catalog.read` |
| Учитель | `lms.content.read`, `assessment.quizzes.write`, `assessment.submissions.grade`, `journal.grades.write`, `library.recommendations.create` |
| Классный руководитель | права учителя + `org.members.read`, `journal.summary.read` |
| Администрация школы | `iam.users.write`, `iam.groups.write`, `org.classes.write`, `journal.schedule.write`, `analytics.reports.read` |
| Методист | `lms.content.write`, `lms.content.publish`, `assessment.quizzes.write`, `ai.validate.use` |
| Психолог | `safety.support.use`, `safety.incidents.manage`, `journal.summary.read` |
| Секретариат | `documents.requests.process`, `documents.templates.read`, `org.members.read` |
| Родитель | `journal.grades.read`, `journal.attendance.read`, `library.catalog.read`, `documents.requests.create` |
| Администрация города | права школы + `org.schools.write`, `admin.region.manage`, `analytics.bi.read` |
| Администрация области | права города + `admin.region.manage`, `analytics.reports.export` |
| Республиканская администрация | все права, включая `admin.country.manage`, `system.services.write` |

Матрица не является жёсткой: администратор может создать собственную группу
и выдать любой набор прав из каталога.

## 6. Управление группами

### 6.1. API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/groups` | список групп в доступных областях |
| POST | `/api/v1/groups` | создать группу |
| GET | `/api/v1/groups/{id}` | карточка группы с участниками и правами |
| PATCH | `/api/v1/groups/{id}` | изменить группу |
| DELETE | `/api/v1/groups/{id}` | отключить группу (системные — запрещено) |
| POST | `/api/v1/groups/{id}/members` | добавить пользователей |
| DELETE | `/api/v1/groups/{id}/members/{user_id}` | исключить пользователя |
| PUT | `/api/v1/groups/{id}/permissions/{code}` | выдать право (`allow`/`deny`) |
| DELETE | `/api/v1/groups/{id}/permissions/{code}` | снять право |
| GET | `/api/v1/groups/permissions` | каталог прав |
| GET | `/api/v1/me/permissions` | действующие права пользователя |
| GET | `/api/v1/me/services` | доступные сервисы |

### 6.2. Границы полномочий

Администратор может управлять только своей областью и её потомками:

- республиканский — всей страной;
- областной — своей областью, её городами и школами;
- городской — своим городом и его школами;
- школьный — своей школой и её классами;
- классный руководитель — своим классом (по делегированию).

Попытка выйти за границу возвращает `403`.

### 6.3. Пример: перевод учителя в завучи

```http
DELETE /api/v1/groups/{teachers_group_id}/members/{user_id}
POST   /api/v1/groups/{administration_group_id}/members
{
  "user_ids": ["<user_id>"],
  "is_primary": true
}
```

После этого `GET /api/v1/me/permissions` вернёт права администрации,
унаследованные от школьной, городской, областной и республиканской групп.

## 7. Переходный период

Пока пользователь не добавлен ни в одну группу, действует временное
сопоставление старой роли `users.role` с набором прав (мост совместимости).
Как только пользователь добавлен в группу, мост перестаёт применяться, и
доступ определяется только группами. Это позволяет внедрять модель без
одномоментной остановки пилота.

Мост описан в `app/services/access.py` (`LEGACY_ROLE_PERMISSIONS`) и должен
быть удалён после полного перевода пользователей в группы.

## 8. Безопасность и аудит

- Каждое изменение членства и прав фиксируется: кто, когда, что изменил.
- Выдача прав ограничена каталогом; неизвестное право — `404`.
- Системные группы нельзя удалить или отключить.
- Срок действия членства и права позволяет временные полномочия
  (например, исполняющий обязанности завуча на неделю).
- Все проверки выполняются на API; UI скрывает недоступное, но не является
  средством защиты.
- Для критичных таблиц рассматривается PostgreSQL RLS по `school_id` и scope.
- Экспорт прав и групп — только с правом `iam.audit.read`/`iam.groups.read`.

## 9. Тесты

- Unit: разрешение конфликтов, наследование, срок действия, сервисные
  активации.
- API: создание групп, добавление/исключение участников, выдача прав,
  запрет выхода за область, запрет отключения системной группы.
- Интеграционные: перевод пользователя между группами и проверка нового
  набора прав; отключение сервиса на уровне школы.
- Матрица прав для 8 базовых категорий и 5 уровней иерархии.
