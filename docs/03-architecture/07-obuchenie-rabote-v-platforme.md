## 1. Назначение

Сервис `onboarding` «Обучение работе в платформе» — обязательная часть
республиканской платформы. Он формирует для каждого пользователя персональную
интерактивную программу знакомства с платформой и фиксирует прогресс
прохождения.

Сервис решает четыре задачи:

1. Пользователь проходит обучение не за один раз, а по этапам, возвращаясь в
   удобные дни и недели.
2. Обучение показывает только те сервисы и действия, которые реально
   подключены пользователю и разрешены его правами.
3. Администраторы, руководители школ и учителя видят статус прохождения в
   пределах своей иерархии.
4. При включении нового сервиса у пользователя появляется только
   дополнительный блок «дообучение», без повторного прохождения всего курса.

## 2. Активация и права

| Параметр | Значение |
|---|---|
| Код сервиса | `onboarding` |
| Название | Обучение работе в платформе |
| Категория | `education` |
| API | `/api/v1/onboarding` |
| Маршрут веб-клиента | `/onboarding` |
| Включён по умолчанию | Да |
| Зависимости | `system`, `iam`, `org` |

Сервис включён по умолчанию на уровне страны и не является ядровым. Это
позволяет администратору отключить обучение для выбранной области, города,
школы или класса. Отчётность при этом остаётся доступной: для просмотра
отчётов проверяется право `onboarding.progress.read`, а не активация сервиса.

Публикуемые права:

| Право | Назначение |
|---|---|
| `onboarding.courses.read` | Проходить персональную программу и сохранять шаги |
| `onboarding.progress.read` | Смотреть сводку и прогресс пользователей в своём контуре |
| `onboarding.progress.manage` | Сбрасывать прогресс и управлять обучением |

## 3. Персональная программа

Каталог обучения хранится в коде (`backend/app/services/onboarding_catalog.py`)
и версионируется. Версия текущего каталога — `1.0.0`. В каталоге 15 модулей,
объединённых в 5 этапов:

| Этап | Содержание |
|---|---|
| `start` | Первый вход, навигация, безопасность аккаунта |
| `core` | Пользователи, структура школы, группы и аудит |
| `daily` | Учебный контент, журнал, работы и библиотека |
| `management` | Аналитика, документы, администрирование |
| `advanced` | Коммуникации, безопасность и ИИ-помощник |

Модуль виден пользователю, если одновременно выполнены условия:

1. сервис модуля включён для его области;
2. роль пользователя подходит модулю (если роль ограничена);
3. у пользователя есть хотя бы одно из требуемых прав модуля.

Порядок этапов фиксирован, внутри этапа модули сортируются по времени
прохождения. Прогресс сохраняется после каждого шага, поэтому обучение можно
прервать и продолжить позже.

### 3.1. Новый сервис и дообучение

В `onboarding.profiles.known_service_codes` хранятся коды сервисов, которые уже
были в программе пользователя. Если администратор включает новый сервис,
модуль этого сервиса появляется с признаком `is_addon = true` — это и есть
«дообучение».

После первого запуска модуля сервис добавляется в `known_service_codes`, и
признак дообучения снимается. Завершённые ранее модули не сбрасываются.

## 4. Интерактивный режим

Веб-клиент использует глобальный `CoachProvider` и слой `CoachOverlay`,
которые сохраняют сессию обучения при переходах между маршрутами.

Шаг обучения содержит:

- заголовок и объяснение;
- целевой элемент `target` (CSS-селектор);
- маршрут `route`, если элемент находится на другой странице;
- подсказку `tip`;
- тип действия `action` (`next` или `click`);
- ожидаемое время `duration_seconds`.

Оверлей:

- затемняет фон и оставляет «прожектор» вокруг целевого элемента;
- показывает анимированный указатель и пульсирующее выделение;
- выводит всплывающую подсказку с прогрессом шага;
- автоматически переходит на нужный маршрут;
- ждёт нажатия на подсвеченный элемент для шагов типа `click`;
- позволяет вернуться к предыдущему шагу или закрыть обучение.

Целевые элементы размечены атрибутами `data-onboarding-nav` и
`data-onboarding="page-content"`. Это позволяет развивать обучение без
привязки к хрупким CSS-классам.

## 5. Модель данных

### 5.1. `onboarding.profiles`

| Поле | Назначение |
|---|---|
| `user_id` | Пользователь, уникальный профиль |
| `known_service_codes` | Сервисы, уже вошедшие в программу |
| `catalog_version` | Версия каталога, с которой работал пользователь |
| `last_seen_at` | Последнее открытие программы |

### 5.2. `onboarding.module_progress`

| Поле | Назначение |
|---|---|
| `user_id`, `module_code` | Уникальная пара пользователь-модуль |
| `service_code` | Сервис, к которому относится модуль |
| `status` | `not_started`, `in_progress`, `completed`, `skipped` |
| `current_step_code` | Следующий незавершённый шаг |
| `completed_step_codes` | Упорядоченный список завершённых шагов |
| `started_at`, `last_activity_at`, `completed_at` | Временные отметки |

Статус пользователя в отчёте вычисляется по его модулям: нет начатых —
`not_started`, все завершены — `completed`, иначе `in_progress`.

## 6. API

### 6.1. Обучение

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/onboarding/me` | Персональная программа по этапам |
| `GET` | `/api/v1/onboarding/me/modules/{code}` | Модуль и его шаги |
| `POST` | `/api/v1/onboarding/me/modules/{code}/start` | Начать или продолжить модуль |
| `POST` | `/api/v1/onboarding/me/modules/{code}/steps/{step}/complete` | Завершить шаг |

### 6.2. Отчёты

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/onboarding/reports/summary` | Сводка по пользователям |
| `GET` | `/api/v1/onboarding/reports/users` | Список пользователей и прогресс |
| `GET` | `/api/v1/onboarding/reports/export.csv` | Выгрузка отчёта |
| `POST` | `/api/v1/onboarding/reports/users/{id}/reset` | Сброс прогресса пользователя |

Фильтры отчётов: `school_id`, `role`, `status`, `search`, `limit`, `offset`.
Выгрузка CSV использует те же фильтры и пишется в UTF-8 с BOM для Excel.

## 7. Иерархия отчётов

| Роль | Что видит |
|---|---|
| Республиканский администратор | Все школы и пользователей |
| Администратор области/города | Школы своей области/города |
| Руководитель школы | Пользователей своей школы |
| Учитель | Только своих учеников: по предметам, расписанию и классному руководству |
| Родитель | Только своих детей |
| Ученик | Только собственный прогресс |

Проверка выполняется на сервере. Параметр `school_id` не позволяет выйти за
пределы доступных школ: при попытке запросить чужую школу возвращается `403`.
Сброс прогресса требует `onboarding.progress.manage` и фиксируется в аудите.

## 8. Веб-клиент

| Маршрут | Назначение | Доступ |
|---|---|---|
| `/onboarding` | Программа по этапам, дообучение, прогресс | `onboarding.courses.read` |
| `/onboarding/:moduleCode` | Карточка модуля и шагов | `onboarding.courses.read` |
| `/onboarding/reports` | Отчёты, фильтры, CSV, сброс | `onboarding.progress.read` |

В боковом меню обучение вынесено в отдельный раздел «Обучение работе» и не
дублируется среди динамических образовательных сервисов. Если сервис отключён
для пользователя, прохождение курса недоступно, но отчёты продолжают работать
для тех, у кого есть право на просмотр прогресса.

## 9. Безопасность и ограничения

- В прогрессе не хранятся ответы, персональные документы или иные лишние ПДн.
- Отчёты содержат только имя, логин, роль, школу и агрегированный прогресс.
- Сброс прогресса и выгрузка фиксируются в журнале аудита.
- Обучение не заменяет инструктаж по информационной безопасности и не
  отменяет требования согласий на обработку ПДн.
- Контент каталога проходит методическую проверку перед изменением версии.

## 10. Развитие

- добавление видеошпаргалок и озвучивания шагов;
- A/B-проверка сценариев обучения;
- напоминания о незавершённых этапах через сервис коммуникаций;
- сертификаты и уровни освоения;
- отдельные траектории для родителей и учеников;
- экспорт отчётов в форматах вышестоящих органов управления.
