# Веб-клиент и личный кабинет

| Параметр | Значение |
|---|---|
| Код документа | ШК-03-06 |
| Версия | 1.0 |
| Статус | Рабочий |
| Дата | 30.10.2026 |
| Связанные документы | ШК-03-03, ШК-03-04, ШК-03-05, ШК-07-01 |

## 1. Назначение

Веб-клиент — единая точка входа в платформу «Школьник» для администраторов
республиканского, школьного и классного уровней. Клиент не дублирует
бизнес-правила: права, активации сервисов и состав групп определяются API.
Интерфейс только показывает доступное пользователю и не позволяет выполнить
действие без соответствующего права.

## 2. Технологический стек

| Слой | Решение |
|---|---|
| UI | React 18, TypeScript strict, functional components |
| Сборка | Vite 5 |
| Стили | TailwindCSS 3, дизайн-токены brand/accent |
| Маршрутизация | React Router 6 |
| HTTP | Axios, JWT access/refresh, автоматическое обновление сессии |
| Иконки | lucide-react |
| Утилиты классов | clsx-подобный `cn` на базе `tailwind-merge` |

Node.js в рабочей среде может отсутствовать, поэтому для локальной сборки
используется переносимый дистрибутив в `.tools/` (не коммитится).

## 3. Структура

```text
frontend/src/
  api/          # типы контрактов и клиент API
  auth/         # AuthContext, ProtectedRoute
  access/       # AccessContext: /me/permissions, /me/services
  layout/       # AppLayout: боковое меню, верхняя панель
  pages/        # Login, Dashboard, Groups, Services, Profile, сервисные экраны
  components/   # UI-кит: Button, Card, Badge, Modal, Toggle, EmptyState
  lib/          # метки ролей/уровней/категорий, форматирование, cn
```

## 4. Маршруты

| Маршрут | Назначение | Доступ |
|---|---|---|
| `/login` | Вход | Публичный |
| `/` | Дашборд, показатели школы, сервисы, статус API | Авторизованный |
| `/groups` | Группы, участники, права, наследование | `iam.groups.read` |
| `/services` | Каталог 14 сервисов и активации по уровням | `system.services.read` |
| `/profile` | Профиль, группы, действующие права и запреты | Авторизованный |
| `/journal`, `/library`, `/lms`, `/assessment` | Экраны образовательных сервисов | Сервис включён |
| `/analytics`, `/communication`, `/documents`, `/safety`, `/ai`, `/admin` | Экраны управленческих сервисов | Сервис включён |
| `/service/:code` | Универсальная карточка сервиса | Авторизованный |
| `/404` | Страница не найдена | Авторизованный |

## 5. Аутентификация и доступ

- `AuthContext` хранит access/refresh-токены и профиль пользователя, проверяет
  сессию через `/auth/me`, выполняет refresh при 401 и очищает сессию при
  неудачном обновлении.
- `AccessContext` загружает `/me/permissions` и `/me/services`; на их основе
  строит `Set` разрешённых кодов, список групп и доступных сервисов.
- `can(code)` используется для скрытия действий и пунктов меню.
- `PermissionGate` защищает маршруты администрирования; API дополнительно
  проверяет право на сервере.
- Боковое меню формируется динамически: образовательные и управленческие
  сервисы берутся из `/me/services`, административные разделы — из прав.
- Запреты `deny` отображаются в профиле отдельно; на равной глубине они
  побеждают `allow` по правилам ШК-03-05.

## 6. Экраны

### 6.1. Вход

Двухпанельный экран с описанием платформы, формой логина/пароля и обработкой
ошибок API. Пароль не логируется и не сохраняется в коде.

### 6.2. Дашборд

Показывает приветствие, выбранную школу (для супер-администратора — переключатель
школ), число пользователей, классов, групп и включённых сервисов. Отдельно
выводятся карточки сервисов, состояние `/health`, сводка по ролям и группы
текущего пользователя. Данные статистики запрашиваются с `school_id`.

### 6.3. Группы и права

Таблица групп с фильтрами по уровню, категории и активности. Карточка группы
показывает участников, права `allow`/`deny`, дочерние группы и позволяет
добавлять права и участников при наличии `iam.groups.write`. Для школьных групп
участники выбираются из пользователей школы; для классных и выше интерфейс
показывает правило синхронизации.

### 6.4. Сервисы

Каталог сервисов с переключателем уровня «республика / школа», поиском и
фильтром по категории. Показывает источник активации (`core`, `activation`,
`default`), зависимости и число прав в манифесте. Ядро отключить нельзя.
Изменения сразу применяются через `PUT /services/{code}/activation`.

### 6.5. Профиль

Карточка пользователя, членство в группах, действующие права по сервисам и
явные запреты. Кнопка обновления доступа повторно загружает
`/me/permissions` и `/me/services`.

### 6.6. Сервисные экраны

Для модулей, у которых API уже реализован, но интерфейс ещё не готов, выводится
универсальная карточка: описание, манифест, права, зависимости, статус
активации и ссылка на Swagger. Это позволяет проверять контракт до появления
полного экрана.

## 7. Интеграция с API

- Базовый путь: `/api/v1`.
- В разработке Vite проксирует `/api` и `/health` на `http://127.0.0.1:8000`.
- В пилоте клиент и API находятся на одном домене, поэтому используются
  относительные URL.
- `GET /health` не проходит через `/api/v1`; клиент выбирает относительный путь
  либо origin из `VITE_API_URL`.
- Ошибки API приводятся к читаемому виду, секреты и токены не выводятся.

## 8. Сборка и публикация

```powershell
cd frontend
npm install
npm run typecheck
npm run build
```

Собранный `frontend/dist` может раздаваться тем же FastAPI-приложением:
- `/assets/*` — статические файлы;
- `/` и клиентские маршруты — `index.html`;
- `/api/*`, `/health`, `/docs`, `/openapi.json`, `/robots.txt` — без изменений.

Если `frontend/dist` отсутствует, FastAPI возвращает прежний JSON на `/`, что
сохраняет совместимость backend-only развёртывания.

## 9. Безопасность

- В коде и репозитории нет паролей, токенов и реальных ПДн.
- Для пилота токены хранятся в `localStorage`; для промышленного контура
  рекомендуется httpOnly-cookie или BFF-схема.
- Все действия администратора фиксируются backend-аудитом.
- HTTPS, HSTS и security headers обеспечиваются пилотным сайтом.
- До внедрения CSP необходимо добавить политику для inline-стилей Vite/Tailwind.
- Персональные данные детей не отображаются в списках без необходимости.

## 10. Ограничения и следующие шаги

- Полные экраны журнала, библиотеки, LMS, оценивания, документов и AI ещё не
  реализованы; используются сервисные карточки.
- Автоматизированные E2E-тесты (Playwright) не подключены.
- Мультиязычность интерфейса (i18n) запланирована; тексты пока русские.
- Мобильные клиенты используют тот же API и будут развиваться отдельно.
