# Веб-клиент и личный кабинет

| Параметр | Значение |
|---|---|
| Код документа | ШК-03-06 |
| Версия | 1.7 |
| Статус | Рабочий |
| Дата | 05.11.2026 |
| Связанные документы | ШК-03-03, ШК-03-04, ШК-03-05, ШК-07-01 |

## 1. Назначение

Веб-клиент — единая точка входа в платформу «ВЕКТОР» для администраторов
республиканского, школьного и классного уровней. Клиент не дублирует
бизнес-правила: права, активации сервисов и состав групп определяются API.
Интерфейс только показывает доступное пользователю и не позволяет выполнить
действие без соответствующего права.

## 2. Технологический стек

| Слой | Решение |
|---|---|
| UI | React 18, TypeScript strict, functional components |
| Сборка | Vite 5 |
| Стили | TailwindCSS 3, дизайн-токены brand/accent |
| Маршрутизация | React Router 7.18.5 |
| HTTP | Axios, JWT access/refresh, автоматическое обновление сессии |
| Иконки | lucide-react |
| Утилиты классов | clsx-подобный `cn` на базе `tailwind-merge` |

Node.js в рабочей среде может отсутствовать, поэтому для локальной сборки
используется переносимый дистрибутив в `.tools/` (не коммитится).

## 3. Структура

```text
frontend/src/
  api/          # типы контрактов и клиент API
  auth/         # AuthContext, ProtectedRoute
  access/       # AccessContext: /me/permissions, /me/services
  layout/       # AppLayout: боковое меню, верхняя панель
  pages/        # Login, Dashboard, Groups, Services, Profile, сервисные экраны
  components/   # UI-кит: Button, Card, Badge, Modal, Toggle, EmptyState
  lib/          # метки ролей/уровней/категорий, форматирование, cn
```

## 4. Маршруты

| Маршрут | Назначение | Доступ |
|---|---|---|
| `/login` | Вход | Публичный |
| `/` | Дашборд, показатели школы, сервисы, статус API | Авторизованный |
| `/groups` | Группы, участники, права, наследование | `iam.groups.read` |
| `/services` | Каталог 19 сервисов и активации по уровням | `system.services.read` |
| `/profile` | Профиль, группы, действующие права и запреты | Авторизованный |
| `/education/primary` | Начальное образование, 1–4 классы | `primary_education.read` |
| `/education/secondary` | Среднее образование, 5–11 классы | `secondary_education.read` |
| `/education/vocational` | Колледжи и техникумы | `vocational_education.read` |
| `/education/higher` | Университеты и академии | `higher_education.read` |
| `/journal`, `/library`, `/lms`, `/assessment` | Экраны образовательных сервисов | Сервис включён |
| `/analytics` | Аналитика школы: оценки, посещаемость, классы, CSV | `analytics.reports.read` или `analytics.bi.read` |
| `/onboarding` | Персональная программа обучения и дообучение | `onboarding.courses.read` |
| `/onboarding/:moduleCode` | Интерактивный модуль и шаги | `onboarding.courses.read` |
| `/onboarding/reports` | Отчёты о прохождении обучения | `onboarding.progress.read` |
| `/safety` | Безопасность и психологическая поддержка | `safety.support.use` или другое право `safety.*` |
| `/communication`, `/documents`, `/ai`, `/admin` | Экраны управленческих сервисов | Сервис включён |
| `/service/:code` | Универсальная карточка сервиса | Авторизованный |
| `/404` | Страница не найдена | Авторизованный |

## 5. Аутентификация и доступ

- `AuthContext` хранит access/refresh-токены и профиль пользователя, проверяет
  сессию через `/auth/me`, выполняет refresh при 401 и очищает сессию при
  неудачном обновлении.
- `AccessContext` загружает `/me/permissions` и `/me/services`; на их основе
  строит `Set` разрешённых кодов, список групп и доступных сервисов.
- `can(code)` используется для скрытия действий и пунктов меню.
- `PermissionGate` защищает маршруты администрирования; API дополнительно
  проверяет право на сервере.
- Боковое меню формируется динамически: образовательные и управленческие
  сервисы берутся из `/me/services`, административные разделы — из прав.
- Запреты `deny` отображаются в профиле отдельно; на равной глубине они
  побеждают `allow` по правилам ШК-03-05.

## 6. Экраны

### 6.1. Вход

Двухпанельный экран с описанием платформы, формой логина/пароля и обработкой
ошибок API. Пароль не логируется и не сохраняется в коде.

### 6.2. Дашборд

Показывает приветствие, выбранную школу (для супер-администратора — переключатель
школ), число пользователей, классов, групп и включённых сервисов. Отдельно
выводятся карточки сервисов, состояние `/health`, сводка по ролям и группы
текущего пользователя. Данные статистики запрашиваются с `school_id`.

### 6.3. Группы и права

Таблица групп с фильтрами по уровню, категории и активности. Карточка группы
показывает участников, права `allow`/`deny`, дочерние группы и позволяет
добавлять права и участников при наличии `iam.groups.write`. Для школьных групп
участники выбираются из пользователей школы; для классных и выше интерфейс
показывает правило синхронизации.

### 6.4. Сервисы

Каталог сервисов с переключателем уровня «республика / школа», поиском и
фильтром по категории. Показывает источник активации (`core`, `activation`,
`default`), зависимости и число прав в манифесте. Ядро отключить нельзя.
Изменения сразу применяются через `PUT /services/{code}/activation`.

### 6.5. Профиль

Карточка пользователя, членство в группах, действующие права по сервисам и
явные запреты. Кнопка обновления доступа повторно загружает
`/me/permissions` и `/me/services`.

### 6.6. Сервисные экраны

Для модулей, у которых API уже реализован, но интерфейс ещё не готов, выводится
универсальная карточка: описание, манифест, права, зависимости, статус
активации и ссылка на Swagger. Это позволяет проверять контракт до появления
полного экрана.

### 6.7. Обучение работе в платформе

Раздел `/onboarding` показывает персональную программу по пяти этапам,
прогресс, текущий модуль и блоки дообучения. Карточка модуля содержит шаги и
переход к интерактивному прохождению. Глобальный `CoachProvider` сохраняет
сессию при переходах, а `CoachOverlay` затемняет фон, подсвечивает целевой
элемент, рисует анимированный указатель и показывает подсказку. Страница
`/onboarding/reports` доступна администраторам, руководителям и учителям:
учитель видит только своих учеников, руководитель — свою школу.

### 6.8. Аналитика школы

Раздел `/analytics` показывает численность, распределение оценок,
посещаемость, срез по предметам и классам, выбор учебного года и выгрузку
CSV. Для супер-администратора обязателен выбор школы; остальные пользователи
видят только свою школу. Экран не показывает комментарии и ответы учеников.

### 6.9. Ступени образования

Четыре маршрута `/education/{level}` используют общий экран
`EducationLevelPage`. Для республиканского администратора доступен выбор
учреждения, создание учреждения нужного типа и создание программ. Экран
показывает учебный год, численность, группы, кураторов, программы и
академические профили. Для профессиональных ступеней видны зачётные книжки,
курс, форма финансирования и академический статус; при наличии права
`{service}.profiles.manage` доступны формы создания и редактирования профилей
обучающихся и преподавателей. Управление программами требует права
`{service}.programs.manage`, просмотр профилей — `{service}.profiles.read`.

Блок «Учебные планы и кредиты» показывает планы по программам и учебным
годам, статус, суммарные кредиты и количество компонентов. План
раскрывается в таблицу дисциплин, модулей, практик и курсовых работ с
семестром, кредитами, часами и формой аттестации. При праве
`{service}.programs.manage` доступны создание и редактирование плана,
добавление, изменение и удаление компонентов. В архивный план компоненты
не добавляются.

Блок «Сессии, ведомости и кредиты» показывает сессии по учебному году,
раскрывает ведомости группы и компонента, позволяет массово выставить оценки,
результаты и кредиты, утвердить ведомость, создать перезачёт и одобрить или
отклонить его. Зачётная книжка выбранного обучающегося показывает итоговые
кредиты, процент выполнения плана и основания — утверждённые ведомости или
одобренные перезачёты. Управление требует права
`{service}.programs.manage`, чтение — `{service}.read`.

Блок «Компетенции и матрица» содержит каталог универсальных, общих и
профессиональных компетенций с поиском и фильтрами. Для выбранной программы
задаются целевой уровень 1–5 и вес каждой компетенции. Для учебного плана
отображается матрица «компонент × компетенция»: отметка связи и вес вклада.
Создание и изменение компетенций, матрицы программы и матрицы плана требуют
права `{service}.programs.manage`; чтение доступно по `{service}.read`.

Блок «Практика и договоры» показывает партнёрские предприятия, договоры,
практикантов и дневник выбранного обучающегося. Для предприятия доступны
код, название, отрасль, адрес и контакты. Договор связывает предприятие,
программу и практический компонент учебного плана, содержит номер, учебный
год, период, дату подписания и статус. Распределение фиксирует обучающегося,
группу, руководителя от учреждения, наставника предприятия, период и
плановые часы. Дневник позволяет добавлять записи, утверждать или отклонять
их, а также выставлять итоговый результат и оценку 1–10. Управление требует
права `{service}.programs.manage`; чтение — `{service}.read`.

### 6.10. Безопасность и психологическая поддержка

Раздел `/safety` использует API `/api/v1/safety` и показывается только при
наличии хотя бы одного права `safety.*`. Вкладки формируются по правам:

| Вкладка | Право | Возможности |
|---|---|---|
| Мои обращения | `safety.support.use` | создание обращения, анонимность, согласие, ответ психолога |
| Обращения школы | `safety.incidents.manage` | очередь обращений, ответ, закрытие |
| Инциденты | `safety.incidents.read` или `safety.incidents.manage` | фильтры, регистрация, принятые меры |
| Согласия | `safety.consents.manage` | выдача и отзыв согласий, срок действия |
| Геолокация | `safety.geolocation.read` | последние точки, событие, точность |
| Настройки | `safety.settings.manage` | сроки хранения, порог согласия, анонимность, геолокация, очистка |

Если сервис не активирован, экран показывает состояние «сервис отключён» и
не вызывает защищённые методы. Для республиканского администратора доступен
выбор школы; настройки без выбранной школы применяются как глобальные.
Анонимное обращение не привязывается к учётной записи, поэтому после
отправки показывается его номер. Геолокация принимается только при активном
согласии законного представителя и включённой настройке школы.

## 7. Интеграция с API

- Базовый путь: `/api/v1`.
- В разработке Vite проксирует `/api` и `/health` на `http://127.0.0.1:8000`.
- В пилоте клиент и API находятся на одном домене, поэтому используются
  относительные URL.
- `GET /health` не проходит через `/api/v1`; клиент выбирает относительный путь
  либо origin из `VITE_API_URL`.
- Ошибки API приводятся к читаемому виду, секреты и токены не выводятся.
- Уведомления communication доступны через `fetchNotifications`,
  `markNotificationRead` и `sendNotification`; экран уведомлений появится
  отдельным этапом.
- Заявки документов доступны через `fetchMyDocumentRequests`,
  `fetchSchoolDocumentRequests`, `createDocumentRequest`,
  `processDocumentRequest` и `cancelDocumentRequest`; экран секретариата
  появится отдельным этапом.
- Безопасность использует `fetchMySafetyAppeals`, `fetchSafetyAppeals`,
  `createSafetyAppeal`, `respondSafetyAppeal`, `closeSafetyAppeal`,
  `fetchSafetyIncidents`, `createSafetyIncident`, `resolveSafetyIncident`,
  `fetchSafetyConsents`, `createSafetyConsent`, `revokeSafetyConsent`,
  `fetchSafetyGeolocation`, `fetchSafetySettings`, `updateSafetySettings` и
  `purgeSafetyData`.

## 8. Сборка и публикация

```powershell
cd frontend
npm install
npm run typecheck
npm test
npm run build
npm run test:e2e
```

`test:e2e` требует `PILOT_LOGIN`/`PILOT_PASSWORD`; тесты read-only и
используют gitignored storage state `e2e/.auth/user.json`.

Собранный `frontend/dist` может раздаваться тем же FastAPI-приложением:
- `/assets/*` — статические файлы;
- `/` и клиентские маршруты — `index.html`;
- `/api/*`, `/health`, `/docs`, `/openapi.json`, `/robots.txt` — без изменений.

Если `frontend/dist` отсутствует, FastAPI возвращает прежний JSON на `/`, что
сохраняет совместимость backend-only развёртывания.

## 9. Безопасность

- В коде и репозитории нет паролей, токенов и реальных ПДн.
- Для пилота токены хранятся в `localStorage`; для промышленного контура
  рекомендуется httpOnly-cookie или BFF-схема.
- Все действия администратора фиксируются backend-аудитом.
- HTTPS, HSTS и security headers обеспечиваются пилотным сайтом.
- До внедрения CSP необходимо добавить политику для inline-стилей Vite/Tailwind.
- Персональные данные детей не отображаются в списках без необходимости.

## 10. Ограничения и следующие шаги

- Полные экраны журнала, библиотеки, LMS, оценивания, документов и AI ещё не
  реализованы; используются сервисные карточки.
- Экран `/safety` реализован и развёрнут на пилоте; сервис активирован для
  `pilot-school`, глобальная геолокация выключена до отдельного решения.
  Активация и настройка ограничений для других контуров выполняются отдельно.
- Для уведомлений готовы типы и клиент API, но нет колокольчика, счётчика
  непрочитанных и экрана списка.
- Для заявок документов готовы типы и клиент API, но нет экрана секретариата
  и форм создания/обработки.
- Playwright E2E подключён: 4 read-only сценария на пилоте (вход, `/safety`,
  вкладки, настройки, навигация); для `/safety` также есть компонентные
  тесты Vitest.
- Мультиязычность интерфейса (i18n) запланирована; тексты пока русские.
- Мобильные клиенты используют тот же API и будут развиваться отдельно.
