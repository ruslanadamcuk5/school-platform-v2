## 1. Подход
- Поэтапная миграция, а не «большой взрыв».
- Работающий Flask-сервис не останавливается до переключения.
- Каждый этап заканчивается демонстрацией, тестами и обновлением документов.
- Приоритет — сохранение текущего функционала и данных.
- Юридически значимые функции вводятся после согласования.

## 2. Общая длительность
Ориентировочно **20 месяцев** до промышленной эксплуатации при команде
18–22 человека. MVP для пилота — через 8–10 месяцев.

- Журнал изменений обязателен.

### 11.3.1. Администрирование эксплуатационных настроек
Обязательное требование: республиканский администратор (`superadmin`)
управляет из админ-консоли всеми эксплуатационными параметрами, влияющими на
работоспособность платформы, а не только через `.env` и SSH.

- [x] Реестр типизированных runtime-настроек кеша с описанием, допустимыми
  значениями, значением по умолчанию и источником (`env`/БД).
- [x] Кеш: режим (`disabled`, `redis`, `managed-redis-tls`), проверка TLS,
  TTL, префикс ключей, таймауты, fail-open, cooldown после сбоя, политика
  инвалидации и статус соединения. Endpoint и секрет пока read-only из
  `REDIS_URL`; write-only секрет — следующий этап.
- [ ] Другие параметры работоспособности: лимиты запросов, режим
  обслуживания, фоновые задачи, feature flags, таймауты/retry внешних
  интеграций, S3/AI-переключатели, пороги health-check и мониторинга.
- [x] Доступ только `superadmin`; неизменяемый аудит изменений, маскирование
  секретов в GET/логах и валидация значений. MFA, подтверждение опасных
  изменений и история версий — осталось.
- [x] Приоритет настроек: bootstrap-секреты из env, безопасные параметры —
  из БД; смена endpoint требует env/секрет-хранилища и перезапуска.
- [x] Проверки: RBAC, аудит, маскирование, валидация, fail-open и поведение
  при недоступном Redis.
- [ ] Критерий готовности: ни один эксплуатационный параметр не требует
  ручного редактирования `.env` без отображения, проверки и аудита в
  админ-консоли. Для кеша критерий выполнен, кроме смены секрета endpoint.
