# Концепция информационной безопасности

| Параметр | Значение |
|---|---|
| Код документа | ШК-05-01 |
| Версия | 0.3 |
| Статус | Черновик для согласования с ИБ/юристом |
| Дата | 05.11.2026 |

## 1. Цели
- Защитить персональные данные учеников, родителей и сотрудников.
- Обеспечить целостность оценок, журналов, документов и отчётности.
- Обеспечить доступность платформы в учебном процессе.
- Исключить несанкционированный доступ и утечки.
- Обеспечить доказуемость действий и возможность расследования инцидентов.

## 2. Нормативная основа
- Закон Республики Беларусь «О защите персональных данных» № 99-З.
- Закон Республики Беларусь «Об информации, информатизации и защите
  информации».
- Требования ОАЦ при Президенте Республики Беларусь.
- Технические нормативные правовые акты в области защиты информации.
- Локальные политики оператора и приказы учреждения образования.

Конкретный перечень и актуальные редакции — в ШК-09-01. Перед аттестацией
перечень проверяется юристом и специалистом по защите информации.

## 3. Объекты защиты
1. Персональные данные пользователей.
2. Учётные записи и аутентификационные данные.
3. Оценки, журналы, результаты работ.
4. Психологические обращения.
5. Геолокационные данные.
6. Документы и подписи.
7. Контент и интеллектуальная собственность.
8. Академические профили студентов и преподавателей: зачётные книжки,
   курс, финансирование, кафедра, степень.
9. Логи, аудит, резервные копии.
10. Инфраструктура и ключи.

## 4. Модель угроз (кратко)
| Угроза | Последствие | Меры |
|---|---|---|
| Компрометация учётной записи | Доступ к ПДн, оценкам | MFA для админов, пароли, мониторинг |
| Утечка БД | Массовая утечка ПДн | Шифрование, RLS, аудит, минимизация |
| Атака на API | Нарушение работы, утечка | WAF, rate limiting, валидация |
| Вредоносный файл | Заражение, RCE | Антивирус, sandbox, проверка MIME |
| Подмена оценок | Нарушение доверия | Аудит, версии, права, подписи |
| Атака на AI | Утечка промптов/ПДн | Фильтрация, псевдонимизация |
| Инсайдер | Утечка/фальсификация | RBAC, least privilege, аудит |
| Потеря данных | Остановка | Резервные копии, георезервирование |
| DDoS | Недоступность | Anti-DDoS, CDN, лимиты |
| Утечка геоданных | Опасность для ребёнка | Согласия, шифрование, сроки |

## 5. Классификация данных
- **Публичные:** справочники, опубликованные материалы.
- **Внутренние:** расписание, учебные планы.
- **Конфиденциальные:** оценки, посещаемость, документы, академические
  профили, зачётные книжки, сведения о финансировании обучения.
- **Особо чувствительные:** психологические обращения, геоданные детей,
  сведения о здоровье, документы опекунов.

Для особо чувствительных данных — отдельный контур доступа, шифрование,
минимизация и сокращённые сроки хранения.

## 6. Управление доступом
- RBAC с иерархией ролей.
- Принцип наименьших привилегий.
- Проверка tenant (`school_id`) на каждом запросе.
- MFA для администраторов и привилегированных ролей.
- Сессии с коротким access token и ротацией refresh.
- Блокировка после неудачных попыток.
- Отзыв доступа при увольнении/переводе.
- Регулярный пересмотр прав.

## 7. Аутентификация
- Пароли: Argon2id (предпочтительно) или bcrypt.
- Политика сложности и запрет распространённых паролей.
- MFA: TOTP/аппаратные ключи для админов.
- SSO — при наличии утверждённого регламента.
- Для детских профилей — вход через семейный профиль/код, с ограничениями.

## 8. Шифрование
- TLS 1.2+ для всех внешних соединений.
- Шифрование резервных копий.
- Шифрование особо чувствительных полей на уровне приложения.
- Ключи — в KMS/секретном хранилище, не в коде.
- Для государственных каналов — сертифицированные СКЗИ, если требуется.

## 9. Аудит
- Все административные действия.
- Изменение оценок, документов, прав доступа.
- Входы, выходы, неудачные попытки.
- Доступ к психологическим и геоданным.
- Экспорт данных.
- Формат: кто, что, когда, откуда, результат, request_id.
- Срок хранения — по политике, но не меньше требуемого для расследований.
- Защита логов от изменения.

## 10. Безопасность приложений
- OWASP Top 10 как минимальный baseline.
- Валидация входных данных.
- Параметризованные запросы.
- CSP, HSTS, X-Frame-Options, безопасные cookies.
- Защита от CSRF для cookie-сессий.
- Ограничение загрузок и антивирусная проверка.
- Dependency scanning и обновление зависимостей.
- Секреты не в Git.

## 11. Безопасность AI
- Не передавать лишние ПДн в промпты.
- Псевдонимизация перед отправкой во внешний AI.
- Логирование запросов без чувствительных данных.
- Контент-фильтры для детских сценариев.
- Ограничение тем и моделей.
- Ручная проверка критичного контента методистом.
- Возможность отключить AI без остановки обучения.

## 12. Безопасность детей
- Запрет рекламы и стороннего трекинга.
- Приватность по умолчанию.
- Ограничение геоданных.
- Согласие законных представителей.
- Закрытые психологические комнаты.
- Модерация коммуникаций.
- Кнопка сообщения о проблеме.

### 12.1. Реализованные меры сервиса `safety`
- Специальные ПДн (психологическое состояние, здоровье) обрабатываются только
  при согласии субъекта или законного представителя
  (Закон № 99-З, ст. 5, 8).
- Несовершеннолетний моложе порога согласия (по умолчанию 16 лет) действует
  через законного представителя; связь «представитель — ребёнок»
  проверяется по `iam.user_relations`.
- Порог согласия настраивается администратором в диапазоне 16–18 лет; значения
  ниже 16 отклоняются API.
- Анонимные обращения не содержат `student_id` и `requester_id`; анонимность
  можно отключить в настройках школы.
- Геолокация записывается только при активном согласии
  `scope = geolocation`; координаты проверяются по допустимым диапазонам.
- Сроки хранения обращений, согласий, геолокации и инцидентов настраиваются;
  очистка выполняется отдельным вызовом и фиксируется в аудите.
- Чтение и изменение психологических данных, инцидентов и согласий
  ограничены правами `safety.*` и принадлежностью школе; все действия
  попадают в журнал аудита.
- Сервис `safety` по умолчанию отключён и включается республиканским
  администратором для конкретной школы.

## 13. Реагирование на инциденты
1. Обнаружение и регистрация.
2. Классификация и приоритет.
3. Локализация.
4. Устранение.
5. Уведомление ответственных и, при необходимости, regulators.
6. Разбор и корректирующие меры.
7. Обновление документации и тестов.

## 14. Резервное копирование и восстановление
- Ежедневные полные и инкрементальные копии.
- Хранение в отдельном контуре.
- Шифрование копий.
- Регулярные учения по восстановлению.
- Целевые показатели: RPO ≤ 15 минут, RTO ≤ 4 часа для критичных данных.

## 15. Аттестация и проверки
- Определение класса защищённости.
- Модель угроз и требования к СЗИ.
- Внедрение мер.
- Испытания и аттестация в установленном порядке.
- Пентест и устранение замечаний.
- Повторные проверки не реже установленного периода.

## 16. Организационные меры
- Назначение ответственного за ИБ.
- Политики и инструкции.
- Обучение сотрудников.
- Соглашения о конфиденциальности.
- Управление инцидентами.
- Управление изменениями.
- Контроль подрядчиков и внешних сервисов.

## 17. Ограничения документа
Настоящий документ является проектом. Юридически значимые формулировки,
класс защищённости и перечень обязательных мер подлежат уточнению при
обследовании, согласовании с заказчиком и аттестации.
