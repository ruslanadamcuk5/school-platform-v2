# Отчёт о тестировании уведомлений communication

| Параметр | Значение |
|---|---|
| Код документа | ШК-10-17 |
| Версия | 1.0 |
| Статус | Рабочий |
| Дата | 04.11.2026 |
| Проект | ЕОРП «ВЕКТОР» |
| Связанные документы | ШК-03-03, ШК-03-06, ШК-10-04 |

## 1. Объект испытаний

- API уведомлений `/api/v1/communication/notifications`;
- схема `NotificationCreate` и ограничения полей;
- права `communication.notifications.read` и
  `communication.notifications.manage`;
- проверки активации сервиса `communication`;
- типы и клиент уведомлений веб-приложения;
- запись отправки уведомления в журнал аудита.

## 2. Проверенные сценарии

| № | Сценарий | Ожидаемый результат | Статус |
|---|---|---|---|
| 1 | Регистрация прав | Оба права присутствуют в каталоге `communication` | Автотест |
| 2 | Переходный мост ролей | Чтение доступно методисту, учителю, ученику, родителю, психологу и секретарю | Автотест |
| 3 | Отправка уведомлений | Право `manage` есть у администратора и суперадминистратора, у ученика — нет | Автотест |
| 4 | Заголовок | Пробелы по краям удаляются, пустой заголовок отклоняется | Автотест |
| 5 | Текст | Пробелы по краям удаляются, пустой текст сохраняется как `null` | Автотест |
| 6 | Канал | Принимается только `in_app`; `email` отклоняется | Автотест |
| 7 | Список уведомлений | Возвращаются только уведомления текущего пользователя | Код-ревью |
| 8 | Фильтр непрочитанных | Параметр `unread_only` исключает записи с `read_at` | Код-ревью |
| 9 | Отметка прочтения | Своё уведомление получает `read_at` и статус `read`; повтор идемпотентен | Код-ревью |
| 10 | Чужое уведомление | Отметка чужого уведомления возвращает `404` | Код-ревью |
| 11 | Отправка в свою школу | Администратор может отправить уведомление пользователю своей школы | Код-ревью |
| 12 | Отправка в другую школу | Администратор получает `403`; суперадминистратор может отправить любому | Код-ревью |
| 13 | Аудит | Отправка фиксируется действием `communication.notification.send` | Код-ревью |
| 14 | Отключённый сервис | Маршрут уведомлений возвращает `403` | Автотест |
| 15 | Отсутствие права | Пользователь без права чтения получает `403` | Автотест |
| 16 | OpenAPI | Присутствуют три маршрута уведомлений | Автотест |
| 17 | Веб-клиент | Типы и функции клиента проходят `typecheck` и production build | Сборка |
| 18 | Миграции | Новая миграция не требуется: таблица `communication.notifications` уже существует | Код-ревью |

## 3. Автоматические проверки

```text
backend: 150 passed, 2 warnings
ruff: all checks passed
frontend: npm run typecheck — успешно
frontend: npm run build — успешно
OpenAPI: 157 путей, 211 операций
```

Новые и расширенные тесты:

- `tests/test_communication.py` — схема уведомления, права, каталог сервисов
  и наличие маршрутов в OpenAPI;
- `tests/test_module_access.py` — отключение сервиса `communication` и отказ
  при отсутствии права чтения.

## 4. Ограничения проверки

1. Испытания не подключались к реальной PostgreSQL: проверялись схема,
   зависимости FastAPI, каталог прав и OpenAPI.
2. Уведомления не добавлены в пилотный seed; после доставки кода список
   пользователя будет пустым до отправки первого уведомления.
3. Email, push и мессенджер не реализованы: канал ограничен `in_app`.
4. Живые HTTP-проверки на пилоте не выполнялись, потому что код ещё не
   доставлен.

## 5. Вывод

Уведомления communication реализованы как первый защищённый срез сервиса:
активация, права, ограничения схемы, аудит и OpenAPI проверены. Доставка на
пилот выполняется только после отдельного распоряжения.
