| Параметр | Значение |

| Код документа | ШК-10-14 |

## 1. Объект испытаний

- миграция `0006_sessions_credits`;
- таблицы `org.academic_sessions`, `org.session_statements`,
  `org.statement_records`, `org.credit_transfers`;
- API сессий, зачётных ведомостей, массового внесения результатов,
  зачётной книжки и перезачёта кредитов;
- веб-блок «Сессии, ведомости и кредиты» на экране `/education/{level}`;
- синтетические данные пилотного seed для сессий и перезачётов.

| 6 | Создание ведомости | Ведомость привязана к сессии, группе, плану и компоненту | Успешно |

## 3. Автоматические проверки

```text
backend: 136 passed
ruff: all checks passed
frontend: npm run typecheck — успешно
frontend: npm run build — успешно
alembic offline SQL: 0006_sessions_credits — успешно
```

Новые и расширенные тесты:

- `tests/test_education_levels.py` — валидация сессий, ведомостей,
  результатов и перезачётов, проверка наличия маршрутов в OpenAPI;
- `tests/test_openapi.py` — отсутствие профессиональных маршрутов у школьных
  ступеней;
- `tests/test_pilot_data.py` — импорт и базовые инварианты пилотного seed.

## 4. Ограничения проверки

1. Миграция `0006_sessions_credits` проверена генерацией offline SQL, но не
   применялась к пилотной PostgreSQL до отдельной команды.
2. Обновлённый пилотный seed не запускался на пилоте; синтетические сессии и
   перезачёты появятся после миграции и повторного seed.
3. Живые HTTP-проверки новых маршрутов на пилоте не выполнялись, потому что
   код и схема БД ещё не доставлены.
4. Массовое выставление результатов доступно роли с
   `{service}.programs.manage`; отдельное право преподавателя-экзаменатора
   запланировано на следующий этап.

## 5. Вывод

Функциональность сессий, зачётных ведомостей, зачётной книжки и перезачёта
кредитов реализована и проверена на уровне схемы, API, UI-сборки и
автоматических тестов. Доставка миграции и данных на пилот выполняется только
после отдельного распоряжения.
