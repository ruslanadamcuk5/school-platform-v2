## 1. Назначение

Документ фиксирует результат настройки OpenCode для проекта
`school-platform-v2`: какие изменения внесены, что подтверждено замерами,
какую экономию токенов и времени это даёт и какие ограничения остаются.

Отчёт не заменяет финансовый или биллинговый расчёт: точные токены зависят от
токенизатора модели, размера истории, кеша и загруженных схем инструментов.

## 2. Что изменено

### 2.1. Модели

- Основная модель: `opencode/deepseek-v4.1-flash-free`.
- `small_model`: `opencode/claude-haiku-5-5` для коротких служебных операций.
- `explorer`, `test-runner`, `docs-writer` и `browser` переведены на бесплатную
  модель; `reviewer` оставлен на основной модели для качества ревью.
- Глобальный конфиг очищен от невалидного JSON и зависавшего plugin
  `opencode-puter-auth`; проект использует модель из `opencode.json`.

### 2.2. Инструменты и права

- `browser*` и `opencode*` запрещены глобально; для UI-проверок добавлен
  отдельный подагент `@browser`.
- `edit` оставлен в режиме `ask`, чтобы агент не менял файлы без подтверждения.
- Bash переведён на allowlist: разрешены `git status/diff/log/show`, `rg`,
  `pytest`, `ruff`, `tsc`, `scripts/check.ps1`, сборка и генераторы
  документации; `push`, `ssh`, `rm`, Alembic и деплой требуют подтверждения.
- Чтение секретов, `.env*`, `secrets`, `*.pem`, `*.key`, `package-lock.json`
  и сгенерированных DOCX запрещено.
- `general` вызывается только с подтверждением; остальные подагенты разрешены.
- Добавлены лимиты шагов: build — 50, plan — 30, подагенты — 10–25.

### 2.3. Команды и контекст

- `/check` и `/test` выполняются через `test-runner`.
- `/docs`, `/api`, `/release`, `/db-schema`, `/pilot-status` выполняются в
  `build` с `subtask: true`, чтобы их вывод не оставался в основном контексте.
- `AGENTS.md` сокращён, `progress.md` сжат, полная история перенесена в
  `archive/progress-2026.md`.
- `watcher.ignore` расширен: `.git`, кеши, `secrets`, `.env*`, `node_modules`,
  `.venv`, `docs/word`, `frontend/dist`.

## 3. Измерения

Источники: backup `backups/opencode/20261105T112422Z/`, текущие файлы,
разрешённый конфиг OpenCode и локальная БД `opencode.db` (таблица
`session_v2`). Для оценки токенов использован консервативный диапазон
2,5–4 байта на токен: русский текст обычно даёт больше токенов на байт,
латиница и код — меньше.

от того, какие схемы клиент загружает в конкретном режиме.

### 3.1. Что подтверждено

- Сокращение `AGENTS.md`, `progress.md` и чистый выигрыш памяти на задачу.
- Сокращение доступных инструментов `opencode*` с 8 до 1.
- Устранение зависания `opencode debug config` после удаления plugin.
- Разрешение конфига без ошибок: `opencode debug config` завершается с кодом 0.
- Отсутствие изменений кода приложения: `184 passed`, Ruff чистый,
  typecheck успешен; версия API остаётся `0.9.0`.

### 3.2. Что не подтверждено

- Экономия токенов от браузерных схем: в текущем Code Mode каталог всё ещё
  перечисляет 45 браузерных инструментов (отображается 8). Глобальный
  `permission` запрещает вызовы, но фактическое скрытие схем нужно проверить
  после полного перезапуска и в обычном режиме инструментов.
- Точная экономия от подагентов: она зависит от объёма поиска, тестов и
  документации; без A/B-замера можно говорить только о диапазоне.
- Точное ускорение в секундах: замерен только запуск `debug config`; скорость
  выполнения задач зависит от модели, сети и размера контекста.

## 4. Итоговая оценка

Консервативно, без учёта возможного скрытия браузерных схем:

- **1,4–2,7 тыс. токенов на типовой запрос** за счёт памяти и `opencode*`;
- **15–27 тыс. токенов на 10 запросов**;
- **150–270 тыс. токенов на 100 запросов**.

Дополнительно:

- меньше ручных подтверждений bash — ориентировочно 0,5–3 минуты на задачу
  при 10–20 командах;
- вывод тестов и документации остаётся в подагенте, а не в основном контексте;
- `@general` не запускается случайно, поэтому дорогие исследования требуют
  осознанного подтверждения.

Это оценки, а не биллинговый факт. При включённом кеше денежная стоимость
снижается сильнее, чем число токенов; при длинной истории экономия памяти
начинает влиять на стоимость каждого следующего запроса.

## 6. Ограничения

1. Локальная БД OpenCode имеет схему V2 (`session_v2`, 50 миграций), а CLI
   `1.19.4` — V1. Поэтому `opencode db` и `models` из CLI падают; метрики
   получены прямым read-only запросом к SQLite.
2. Точный токенизатор DeepSeek недоступен; оценка по байтам является
   ориентировочной.
3. Нет контрольной группы одинаковых задач до и после; сравнение по файлам и
   каталогу инструментов, а не по биллингу.
4. Браузерные схемы в Code Mode не подтверждённо сокращены.
5. Plugin `opencode-puter-auth` удалён из автозагрузки; если он понадобится,
   его нужно вернуть отдельно и проверить, не возвращается ли зависание.

## 7. Как измерять дальше

1. Согласовать обновление CLI до V2 (`opencode upgrade --major`) или
   использовать V2-бинарник; это устранит ошибку схемы БД.
2. Выполнить 5–10 одинаковых типовых задач до и после следующей оптимизации.
3. Для каждой задачи фиксировать `tokens_input`, `tokens_output`,
   `tokens_cache_read`, `cost` и время выполнения.
4. Для проверок использовать `Measure-Command` вокруг `scripts/check.ps1`;
   текущий ориентир — 99,3 с.
5. Результаты вносить в этот отчёт или в `progress.md`; не смешивать с
   историческими сессиями.

## 8. Вывод

Основная экономия подтверждена в памяти проекта и в сокращении инструментов
`opencode*`. Конфигурация стала безопаснее: `edit` и опасные команды требуют
подтверждения, секреты закрыты от чтения, а тяжёлые проверки и документация
уходят в подагенты. Браузерные схемы и точное ускорение требуют отдельного
замера после перезапуска и согласования CLI с V2.
