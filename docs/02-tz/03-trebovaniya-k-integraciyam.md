## 1. Принципы
- Все интеграции — через адаптеры с версионируемым API.
- Внешние системы не должны быть единой точкой отказа.
- При недоступности внешней системы — очередь, retry, деградация.
- Все входящие и исходящие данные валидируются.
- Секреты и ключи — только в защищённом хранилище.
- Интеграции с государственными системами включаются только после
  согласования регламента и защиты каналов.

## 2. Государственный электронный журнал/дневник
**Назначение:** передача оценок, посещаемости, домашних заданий, расписания.

**Требования:**
- Двусторонняя или односторонняя синхронизация по согласованной схеме.
- Идемпотентность: повторная передача не создаёт дублей.
- Журнал обмена и статусы доставки.
- Ручное подтверждение конфликтов администратором.
- Ограничение доступа к персональным данным.

**Этап:** P1, после юридического согласования.

## 3. РИОС / «Информационное ядро»
**Назначение:** интеграция с республиканской информационно-образовательной
средой, обмен образовательным контентом и данными.

**Требования:**
- Подключение через утверждённые форматы и API.
- Соответствие требованиям оператора.
- Аудит обмена.
- Тестовый контур до промышленного.

**Этап:** P1.

## 4. ЕСИ / SSO
**Назначение:** единая идентификация пользователей.

**Требования:**
- OAuth2/OIDC или утверждённый протокол.
- Сопоставление учётных записей.
- Отказ от хранения пароля государственной системы.
- Graceful degradation при недоступности SSO.

**Этап:** P1/P2.

## 5. Внешние мессенджеры
Поддерживаются: Telegram, Viber, Mattermost и другие — только если включены
администратором.

**Требования:**
- Администратор может полностью отключить внешние каналы.
- При отключении остаётся только встроенный мессенджер.
- Уведомления не должны содержать лишних ПДн.
- Согласие пользователя на внешний канал.

## 6. Видеосервисы
- Встроенный WebRTC-сервис.
- Возможность подключения внешних (Zoom, Google Meet, Jitsi) по настройке.
- Администратор может запретить внешние сервисы.
- Для детских сессий — модерация и закрытые комнаты.

## 7. Геолокация
- Собственный модуль трекинга.
- Возможность подключения Google/Yandex Maps для отображения.
- Согласие законного представителя.
- Минимизация: не хранить историю дольше необходимого.
- Уведомления о входе/выходе из школы.

## 8. Питание
- Загрузка меню из email, API, сетевой папки, ссылки, файла.
- Шаблоны парсинга настраиваются администратором.
- Публикация меню в кабинетах родителей и учеников.
- Опционально — данные о фактическом питании.

## 9. Платежи (при необходимости)
- Только через сертифицированного провайдера.
- Не хранить полные данные карт.
- Отдельное согласование с юристами и бухгалтерией.
- Родительский контроль и история операций.

## 10. AI-провайдеры
- OpenRouter, OpenAI-совместимые API.
- Администратор задаёт провайдера, модель, ключ, лимиты.
- Логи запросов без лишних ПДн.
- Контент-фильтры для детских сценариев.
- Резервный провайдер и деградация.

## 11. Уведомления
- Push (FCM/APNs).
- E-mail.
- Встроенный мессенджер.
- Внешние мессенджеры (по разрешению).
- Настройка типов уведомлений пользователем.
